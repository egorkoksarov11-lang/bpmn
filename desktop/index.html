BPMN — новая компоновка

Выберите BPMN, JSON или YAML. Генератор заново расставит шаги, роли, документы и линии по связям, сохранив бизнес-логику.

Файл обрабатывается на вашем компьютере.

Готов к работе

Журнал работы


Обычно требуется несколько минут. Время зависит от размера схемы; лимит поиска не равен общему времени работы. Исходный файл сохраняется. Для завершения приложения закройте его консольное окно.


Как подготовить JSON или YAML


Начните с готового примера, замените роли, шаги и связи своими и загрузите файл выше. Указывать координаты и размеры не нужно. YAML использует те же поля; расширения .yaml, .yml и .ylm равнозначны. Кодировка — UTF-8.

ПолеЧто указать


schema_versionОбязательно: число 1.


processОбязательно: {id, name} — идентификатор и название процесса.


rolesОбязательно: непустой массив {id, name} — роли участников.


nodesОбязательно: непустой массив {id, type, name, role}. role — id объявленной роли.


flowsОбязательно: массив {id, source, target} — переходы между узлами. source и target — id из nodes. Можно добавить name (подпись) и condition (условие).


documentsНеобязательно: массив {id, type, name}. Тип document — документ, store — база/хранилище.


associationsНеобязательно: массив {id, source, target}. Шаг → документ: выдача; документ → шаг: использование. Каждому документу/хранилищу нужна хотя бы одна такая связь.




Правила id: уникальны во всём файле, включая процесс, роли и связи. Используйте латинские буквы, цифры, _ . -; первый символ — буква или _. Префикс __import_ зарезервирован. Названия name могут быть русскими. Все перечисленные строковые поля — непустые строки; необязательное поле можно не указывать.


Типы nodes: startEvent — начало, endEvent — конец; task, userTask, manualTask, serviceTask, sendTask, receiveTask, businessRuleTask — операции; exclusiveGateway — выбор одной ветви, parallelGateway — параллельные ветви, inclusiveGateway — выбор одной или нескольких ветвей.


Связи определяют порядок. Положение в массиве и номера в названиях его не задают. В начало нельзя входить, из конца нельзя выходить. Документы не являются шагами и связываются через associations. Вложенные подпроцессы, граничные события и межпуловые сообщения этот формат пока не описывает. Неизвестные поля, повторные ключи и ссылки на несуществующие id вызывают понятную ошибку. YAML-якоря не поддерживаются.

Если нужны условия и ветвления


Добавьте шлюз с ролью; необязательное поле default — id его исходящего перехода без условия. Подпись name сама по себе не является условием:


{"id":"decision","type":"exclusiveGateway","name":"Согласовано?","role":"manager","default":"rejected"}

{"id":"approved","source":"decision","target":"pay","name":"Да","condition":"approved == true"}
{"id":"rejected","source":"decision","target":"revise","name":"Нет"}


Узлы pay и revise должны быть объявлены в nodes. Условия сохраняются дословно как BPMN formalExpression и не выполняются генератором. У startEvent и parallelGateway исходящие условия запрещены; default разрешён у exclusiveGateway/inclusiveGateway. Цикл задайте переходом к уже существующему узлу.


JSON/YAML сначала преобразуется в BPMN, после чего работает прежний алгоритм. Промежуточный input_model.bpmn и отчёт импорта входят в ZIP результата.
