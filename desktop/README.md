# Самостоятельный запуск — Windows 10/11, x64 и ARM64

1. Скачайте `BPMN_Generator_Windows_v23_8_0_experimental.zip` из папки `releases` репозитория.
2. **Распакуйте весь архив** в папку, куда можно записывать файлы, например `Документы\BPMN Generator`. Не запускайте файл внутри ZIP.
3. Дважды нажмите `START_WINDOWS.cmd`. При первом запуске нужен интернет: приложение скачает Python 3.12.10, Node.js 22.14.0 и библиотеки. Прав администратора не требуется. Следите за установкой в открывшемся окне; при ошибке оно останется открытым.
4. В браузере выберите `.bpmn`, `.json`, `.yaml`, `.yml` или `.ylm` и нажмите **«Создать схему»**. Дождитесь результата. Скачайте ZIP или BPMN/SVG отдельно. Структура JSON/YAML и полный пример показаны прямо на первой странице. [Описание всех полей](INPUT_FORMAT.md).

Можно выбрать один или два процесса на общей BPMN Collaboration. В JSON/YAML два процесса описываются через `schema_version: 2`, массив `processes` и объект `collaboration`; отдельные пулы связываются `message_flows`. На странице есть примеры двух процессов для скачивания. Старый формат `schema_version: 1` продолжает работать. Добавлены промежуточные события, определения сообщений и независимые ссылки на один документ.

Все результаты также лежат в `results\дата-время-идентификатор` внутри распакованного пакета. Для каждого запуска создаётся новая папка. В неё записываются копия исходника `original` с его расширением, новая схема `generated.bpmn`, изображение `generated.svg`, отчёты, журнал и `result.zip`. При JSON/YAML также сохраняются промежуточный `input_model.bpmn` и `input_report.json`. Исходный файл не перезаписывается. Название результата не зависит от номера процесса.

Оставляйте консольное окно открытым во время работы. Закрытие вкладки браузера не останавливает генерацию: адрес для повторного открытия напечатан в консоли. Ctrl+C в консоли завершает приложение и останавливает текущую генерацию. Уже записанные результаты сохраняются.

## Как работает

Это локальное приложение: браузер обращается только к `127.0.0.1` на случайном порту. BPMN не загружается в интернет. Нет учётной записи, API-ключей или платных сервисов. Интернет используется для установки зависимостей; повторный запуск проверяет зависимости и при необходимости может обращаться к реестру пакетов.

Запуск использует генератор v23.4 в режиме `scratch`, с лимитом кандидата 60 секунд и бюджетом поиска 200 секунд. Все исходные координаты удаляются перед планированием. Структура выбирается по связям, ролям и типам элементов; названия измеряются только для размещения текста. Номера шагов не определяют порядок. Бизнес-XML и информационные связи проверяются на сохранность; автоматического удаления документов в этом пакете нет.

Полное время может превышать бюджет поиска: проверка, дополнительный контрольный вариант и уточнение линий требуют времени. Обычно это несколько минут; для больших схем — дольше. На Windows лимит кандидата проверяется при выполнении Python-кода; блокирующие внешние вызовы имеют собственные тайм-ауты. Проверенная схема не означает, что найден глобальный оптимум или достигнуто качество ручного эталона. Неподдерживаемые конструкции или не прошедший проверки вариант дают ошибку с журналом, а не непроверенный результат.

## Если не запускается

- Распакуйте архив целиком. Избегайте защищённых каталогов вроде `Program Files` и сетевых папок с запретом запуска.
- При ошибке установки проверьте доступ к `github.com`, `release-assets.githubusercontent.com`, `nodejs.org`, `pypi.org` и `files.pythonhosted.org`, затем повторите запуск. Законченные этапы установки используются повторно.
- Если браузер не открылся, скопируйте полный адрес из консольного окна. Он содержит локальный ключ доступа.
- При ошибке генерации раскройте «Журнал работы»; полный текст находится в `results\…\generation.log`.
- Если администратор организации блокирует `.cmd` или PowerShell, потребуется разрешённый им способ запуска. Скрипт не меняет системную политику PowerShell.

## Разработчикам

Полный код движка включён в ZIP в `src`; запуск интерфейса — `desktop/app.py`. Для macOS/Linux пока предусмотрен ручной запуск с Python ≥3.11 и Node.js ≥18:

```bash
python3 -m venv .venv-desktop
.venv-desktop/bin/pip install -r desktop/requirements.txt
npm ci --ignore-scripts
.venv-desktop/bin/python desktop/app.py
```

Проверка без интерфейса:

```bash
python desktop/app.py --input path/to/process.bpmn --results path/to/results
```

Windows-установщик проверяется отдельным заданием GitHub Actions; статус конкретного запуска смотрите во вкладке Actions. Локальная проверка в среде Linux не заменяет запуск Windows.
