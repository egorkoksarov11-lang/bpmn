# BPMN v23.8 — эксперимент раннего планирования

В этой ветке добавлен графовый планировщик перед размещением и трассировкой. Исходная v23.8 сохранена в [v23.8-readable-turns](https://github.com/egorkoksarov11-lang/bpmn/tree/v23.8-readable-turns). Прототип не заменяет базовую версию. [Реализация и апробация на четырёх крупных процессах](docs/EARLY_COMPOSITION_V23_8.md).

Быстрый анализ BPMN без трассировки:

```bash
python tools/plan_composition.py --input model.bpmn --output plan.json
```

План содержит порядок ролей, число рядов, позиции блоков, предполагаемые переходы и оценки риска. Это проект компоновки; проверки готовой схемы выполняются при полной генерации. Бизнес-логика, названия и принадлежность ролям сохраняются. Текст используется только для измерения размеров. Новых зависимостей нет.

Полная генерация прототипом:

```bash
python run_v23.py --input model.bpmn --output-dir result --layout-engine scratch --candidate-timeout 60 --search-seconds 200
```

Архивы готовых выпусков и показатели ниже относятся к историческим версиям; код нового планировщика находится в этой ветке.

Приняты перенос целого участка и повороты на шагах; на одном из четырёх процессов выросло число контактов. [Сравнение и ограничения](docs/DEVELOPMENT_V23_8.md). Стабильная v23.7 остаётся в [main](https://github.com/egorkoksarov11-lang/bpmn). BPMN / JSON / YAML, один или два процесса. [Структура входа](desktop/INPUT_FORMAT.md).

**[Скачать генератор v23.4.2 для Windows — ZIP](https://raw.githubusercontent.com/egorkoksarov11-lang/bpmn/main/releases/BPMN_Generator_Windows_v23_4_2.zip)**. Распакуйте архив, запустите `START_WINDOWS.cmd`, дождитесь установки и выберите BPMN, JSON или YAML в браузере. Структура JSON и скачиваемые примеры показаны на первой странице. [Инструкция](desktop/README.md) · [формат входных данных](desktop/INPUT_FORMAT.md). Исходники включены; обработка выполняется локально, результаты сохраняются в `results`.

Структура строится по связям, принадлежности ролям и типам BPMN. **Наименования и номера шагов не используются для выбора групп, основного пути и порядка ролей.** Полный текст сохраняется и измеряется для отрисовки.

Добавлены графовые области ветвления и циклов, исправление смещённых портов ромбов/кругов, перенос мешающих соседей с документами, расширение полос ролей и общий цикл «группы → роли → линии → оценка». Готовые коридоры растягиваются вместе с полосами; потерявшие корректность связи перепрокладываются. Используется общая оценка читабельности и компактности, сохраняется лучший полностью проверенный результат.

## Упрощённая схема и порядок ролей

Новый режим `tools/compact_process.py` группирует часто взаимодействующие роли и показывает один документ у первого содержательного шага. Все удалённые графические ссылки и информационные связи записываются в журнал; полная исходная модель сохраняется рядом. Это явное упрощение представления. Операции, исполнители, условия, переходы и определения логических данных проверяются на сохранность.

```bash
python tools/compact_process.py --input path/to/model.bpmn --output-dir compact-result
```

[Скачать обновлённую схему №4](https://raw.githubusercontent.com/egorkoksarov11-lang/bpmn/main/examples/generated/process04/4_result_v2.zip) · [правила упрощения и алгоритм ролей](docs/COMPACT_PRESENTATION.md).

Промежуточная v3 добавляет локальные вертикальные блоки без уменьшения текста: [скачать ZIP](https://raw.githubusercontent.com/egorkoksarov11-lang/bpmn/main/examples/generated/process04/v3-preview/4_result_v3_preview.zip). Размеры 6834×2534 → 4871×1990; контакты 16 → 12, длина sequenceFlow −11,6%, изгибы 77 → 116. Это компромисс, а не улучшение каждого показателя. [Правило упаковки](docs/LOCAL_FOLDING.md). Для включения: `--local-fold --fold-kind hybrid`; все 147 тестов прошли.

Для №4: 71 → 17 информационных связей, 18 → 17 значков документов/баз; суммарная длина межролевых переходов 66 670,6 → 29 737,65 (−55,4%). Проверены 139 тестов. Метрики относятся к этому примеру; весь корпус r10 после добавления режима не пересчитывался. Обычный `run_v23.py` сохраняет строгий режим без удаления документов.

Основной режим `scratch` строит схему по бизнес-графу. Исходные координаты, размеры, маршруты и позиции подписей полностью удаляются до планирования. Бизнес-XML, принадлежность к ролям, документы, базы и все связи сохраняются.

- **Процесс №08:** [SVG](output/process_08_v23.svg) · [BPMN](output/process_08_v23.bpmn) · [независимый аудит](tests/reports/r10/process08_audit.json).

Распакуйте ZIP и откройте `comparison.html`. В нём три варианта каждого успешно построенного процесса: ручной эталон, контроль с нуля и новый алгоритм с нуля. Есть масштаб 1:1, редактируемые BPMN и экспорт SVG; интернет не нужен.

25 из 25 корректных поддерживаемых референсов построены; контроль построил 23. Ещё 7 входов отклонены с причинами. На 23 общих успешных входах изгибов последовательности меньше на 15,1%, длина документных связей меньше на 33,4%; **контактов линий больше на 32,3%**, площадь больше на 6,8%. Улучшение неоднородно. По сравнению с ручными эталонами суммарных изгибов больше на 102,2%, длина переходов больше на 70,5%. Качество референсов и 80% визуального сходства пока не достигнуты.

Для №08 сохранены 64 узла, 95 переходов, 18 информационных связей, 17 информационных объектов и 6 ролей. Прямые переходы: 26,3% → 43,2%; контакты: 190 → 84; длина переходов выросла на 14,7%. Строгие проверки XML, геометрии и полного текста проходят. Одностраничная читаемая печать A4 не достигнута.

```bash
npm ci
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn --output-dir scratch-result --layout-engine scratch --candidate-timeout 90
PYTHONPATH=src/v23:src/v22 .venv/bin/python -m pytest tests src/v22/tests -q
```

Нужны Python ≥3.11 и Node.js. `scratch` выбран по умолчанию; лимит CLI по умолчанию — 30 секунд на кандидат. Изменение времени и нагрузки может менять набор завершённых кандидатов. Результаты актуальных проверок и ограничения перечислены в [отчёте v23.8](docs/DEVELOPMENT_V23_8.md).

Исторические результаты уточнения готового расположения: [r8](docs/DEVELOPMENT_R8.md). Режимы `reference` и `adaptive` выбираются явно; их результаты не доказывают построение с нуля. Исходный v22 не изменён. Исходные архивы, офисные формы и сырая запись работы не публикуются.
