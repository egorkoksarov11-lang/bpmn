# BPMN Universal Engine — v23.1.2 experimental

Автоматическая компоновка BPMN без изменения бизнес-логики. Текущая разработка ищет баланс компактности, разнесения линий и непрерывности чтения шагов.

В новом варианте меньше близких параллельных участков и меньше длинных переходов: 40 → 33. Площадь выросла примерно на 3.5%. При этом контакты выросли с 49 до 60, изгибы — со 178 до 200, тяжесть оставшихся длинных переходов тоже выросла. Обе версии сохранены для сравнения. Итоговый инженерный балл не заменяет визуальную оценку человеком.

Сохранены 64 узла, 95 переходов, 18 документных связей, 17 документных references и 6 дорожек. Semantic diff = 0, DI-структура сохранена. Задачи 220×80, Open Sans 13 px, полный текст без сокращений. **60 тестов прошли**. Читаемая печать всей схемы на одном A4 не достигнута.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn \
  --output-dir output-r3 --candidate-timeout 120 \
  --incumbent examples/process_08_r2.bpmn --orientations-only
PYTHONPATH=src/v23:src/v22 .venv/bin/python -m pytest tests src/v22/tests -q
```

Это команда сравнительного эксперимента с предыдущим проверенным результатом. Для нового BPMN убрать --incumbent и --orientations-only: backend построит до восьми базовых и ориентированных кандидатов с нуля. Прежний вариант сначала проходит полную проверку идентичности frozen-модели; несовместимый или небезопасный incumbent отклоняется. Входные файлы не перезаписываются.

Python ≥3.10; lxml, Pillow и pytest. Шрифт и лицензия включены. Во время компоновки сеть, Graphviz и Node не требуются. Бюджет по умолчанию 150 с на кандидат; эксперимент занял около пяти минут. Результат поиска может зависеть от завершённости A* в выделенный бюджет.

## Что изменено

- Профиль размеров и плотности измерен на 32 человеческих схемах; это набор правил, а не нейросетевое обучение.
- Пара «задача — шлюз» имеет четыре ориентации, учитываются все её связи. Ряды и документы сдвигаются согласованно.
- Маршрутизация учитывает тесное параллельное ведение линий; пучки пересматриваются и без пересечений.
- Выбор учитывает локальную плотность и длины переходов по графу. Веса политики balanced-readability-v1 открыты в коде и требуют дальнейшей проверки на пользовательских оценках.
- Сохранены строгие проверки семантики, DI, геометрии, контуров и полного текста.

Поддерживается ограниченный профиль BPMN с плоскими дорожками. Полная нотация специальных событий не заявляется. Крупные сценарные блоки пока распознаются аналитическим инструментом, но ещё не используются для полной перепаковки основного пути. Архитектура и ограничения: [docs/ARCHITECTURE_V23.md](docs/ARCHITECTURE_V23.md).
