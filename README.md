# BPMN Universal Engine — r10, построение с нуля

Основной режим `scratch` строит схему по бизнес-графу. Исходные координаты, размеры, маршруты и позиции подписей полностью удаляются до планирования. Бизнес-XML, принадлежность к ролям, документы, базы и все связи сохраняются.

- **[Скачать схемы и автономную галерею — ZIP](https://raw.githubusercontent.com/egorkoksarov11-lang/bpmn/main/examples/benchmarks/r10/BPMN_From_Scratch_r10.zip)**
- **Процесс №08:** [SVG](output/process_08_v23.svg) · [BPMN](output/process_08_v23.bpmn) · [независимый аудит](tests/reports/r10/process08_audit.json).
- [Методика, все показатели и ограничения](docs/DEVELOPMENT_R10.md) · [корпусный отчёт](tests/reports/r10/benchmark_report.json) · [архитектура](docs/ARCHITECTURE_V23.md).

Распакуйте ZIP и откройте `comparison.html`. В нём три варианта каждого успешно построенного процесса: ручной эталон, контроль с нуля и новый алгоритм с нуля. Есть масштаб 1:1, редактируемые BPMN и экспорт SVG; интернет не нужен.

25 из 25 корректных поддерживаемых референсов построены; контроль построил 23. Ещё 7 входов отклонены с причинами. На 23 общих успешных входах изгибов последовательности меньше на 15,1%, длина документных связей меньше на 33,4%; **контактов линий больше на 32,3%**, площадь больше на 6,8%. Улучшение неоднородно. По сравнению с ручными эталонами суммарных изгибов больше на 102,2%, длина переходов больше на 70,5%. Качество референсов и 80% визуального сходства пока не достигнуты.

Для №08 сохранены 64 узла, 95 переходов, 18 информационных связей, 17 информационных объектов и 6 ролей. Прямые переходы: 26,3% → 43,2%; контакты: 190 → 84; длина переходов выросла на 14,7%. Строгие проверки XML, геометрии и полного текста проходят. Одностраничная читаемая печать A4 не достигнута.

```bash
npm ci
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn --output-dir scratch-result --layout-engine scratch --candidate-timeout 90
PYTHONPATH=src/v23:src/v22 .venv/bin/python -m pytest tests src/v22/tests -q
```

Нужны Python ≥3.10 и Node.js. `scratch` выбран по умолчанию; лимит CLI по умолчанию — 30 секунд на кандидат, для опубликованного №08 использован 90. Поиск №08 занял около 8 минут в данном окружении. Изменение времени и нагрузки может менять набор завершённых кандидатов. 130 тестов прошли; проверка полного сброса геометрии прошла на всех 25 поддерживаемых входах.

Исторические результаты уточнения готового расположения: [r8](docs/DEVELOPMENT_R8.md). Режимы `reference` и `adaptive` выбираются явно; их результаты не доказывают построение с нуля. Исходный v22 не изменён. Исходные архивы, офисные формы и сырая запись работы не публикуются.
