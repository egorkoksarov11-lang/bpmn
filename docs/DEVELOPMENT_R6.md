# r6 — оптимизация и проверяемое соответствие ручным схемам

Цель — не просто уменьшить площадь, а приблизить последовательность чтения, расстояния между шагами и разделение веток к ручным референсам. Изучены все 32 BPMN из повторно загруженного архива; ошибок чтения нет, 32 уникальных файловых хеша. Архив совпадает с ранее загруженным. Входы и v22 не изменяются.

## Готовые алгоритмы: что применено и что проверено

| Источник | Подход | Решение в r6 |
|---|---|---|
| [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html), [описание фаз](https://eclipse.dev/elk/blog/posts/2025/25-08-21-layered.html) | Устранение циклов в графе размещения, слои, минимизация пересечений, координаты, ортогональная трассировка | Реально подключён elkjs 0.12.1. NETWORK_SIMPLEX задаёт слои; результаты проецируются в неизменные роли. Пары задача/решение — внутренние макроузлы. Возвраты исключаются только из графа размещения; все исходные рёбра сохраняются в BPMN. На №08 этот вариант хуже проверенного incumbent. |
| [bpmn-auto-layout](https://github.com/bpmn-io/bpmn-auto-layout) | Готовая BPMN-компоновка | Проверен релиз 1.3.0, который возвращает XML-строку. README текущей ветки описывает другой API. В эксперименте отсутствует DI для 18 документных связей; полный выход библиотеки не принимается. Различия сериализации сами по себе не доказывают изменение логики. |
| [Graphviz dot](https://graphviz.org/docs/layouts/dot/) | Иерархическая компоновка, crossing minimization, network simplex | Изучен как источник архитектуры. В этом цикле не измерялся как новый полноценный BPMN-backend. |
| [libavoid](https://www.adaptagrams.org/documentation/libavoid.html) | Обход препятствий, ортогональная трассировка и разнесение маршрутов | В собственном роутере проверены аналогичные принципы: коридоры возвратов и повторная прокладка сложных рёбер. Сама библиотека не интегрирована. |

ELK и bpmn-auto-layout устанавливаются через `npm ci` (точные версии и зависимости в lockfile). Это необязательные исследовательские зависимости. Собственный Python-алгоритм работает без Node и сети. Код внешних библиотек в репозиторий не копируется. ELK-проекция пока экспериментальная: на HR12 не нашла места под две подписи событий, на HR13 получила пересечение фигур. Основной Python-backend на тех же двух процессах построил проверенные схемы с semantic diff 0. Это проверка переносимости, а не независимое испытание визуального сходства.

## Метрики

[Профиль](../src/v23/bpmn_v23/assets/reference_conformity_profile.json) фиксируется до выбора компоновки. [Калибровка и исходные измерения](../tests/reports/reference_metrics_r6/reference_report.json) доступны для проверки. Ни названия №08, ни ID его узлов не входят в функцию оценки.

| Семейство | Что измеряем |
|---|---|
| Маршруты | Изгибы на переход, доля прямых линий, p90 изгибов |
| Расстояния | Средняя и p90 длины в ширинах задачи, лишний путь вперёд с учётом настоящих возвратов |
| Пересечения | Контакты sequenceFlow на один переход |
| Скученность | Близкие параллельные линии и локальные зоны плотности |
| Компактность | Площадь относительно фигур, пропорции схемы |
| Выравнивание | Доля связанных фигур с совместимыми осями подключения |
| Документы | Длина и изгибы документных связей |

Контакт — пересечение или неоднозначное касание, а не только геометрический крест. Таблица ниже использует все рёбра; нормированная метрика пересечений использует только sequenceFlow. Различие явно сохранено в JSON.

Для каждой метрики используются p10, p50, p90 референсов; масштаб = max(IQR, 0,25×|медиана|, 0,05). Внутри приемлемой границы балл равен 100, за её пределами плавно падает как exp(−отклонение/(2×масштаб)). Меньше изгибов, длины, скученности и площади не штрафуется. Пропорции оцениваются в обе стороны. Против чрезмерного уплотнения действуют обязательные геометрические и текстовые проверки.

Геометрическое среднее сначала внутри семейств, затем между семействами не позволяет большому числу похожих показателей перевесить остальные. Цель: общий балл ≥80, каждое семейство ≥60 и шесть обязательных проверок: semantic freeze, DI freeze, безопасность трассировки, зазоры, текст/подписи, отсутствие рёбер с >8 изгибами. Промежуточное размещение может иметь больше изгибов до повторной трассировки, но в итог допускается только безопасный вариант; иначе выбирается безопасный резерв или выдаётся ошибка без перезаписи результата. Старый incumbent допускается как исходная точка исправления; это не означает прохождение им всех целевых проверок.

**Этот балл — диагностическое соответствие геометрическим признакам. Он не означает «человек подтвердил 80% сходства».** `visual_similarity_verified` остаётся false. Приёмка по слепой человеческой оценке пока не проведена. Процесс №08 имеет 95 переходов, 64 узла и 17 настоящих возвратов; эти размеры выходят за наблюдаемый диапазон корпуса. Нормализация смягчает, но не устраняет зависимость метрик от сложности.

## Результат

| Показатель | r4 | r6 |
|---|---:|---:|
| Контакты всех линий | 40 | 40 |
| Все изгибы | 199 | 151 |
| Общая длина, единицы DI | 51 990,8 | 49 858,3 |
| Балл соответствия | 57,16 | 70,39 |
| Близкие параллельные линии на переход | 0,047757 | 0,030865 |
| Локальная избыточная плотность | 0,055430 | 0,013036 |
| Избыточная длина вперёд | 1,356108 | 1,249785 |
| Связанные фигуры на совместимых осях | 36,84% | 57,89% |
| Коэффициент площади | 7,3255 | 7,6823 |
| Рёбра с >8 изгибами | 2 | 0 |

Выиграла небольшая жёсткая горизонтальная подвижка содержимого дорожек. Соседние шаги внутри роли остаются на своих местах; документы следуют за связанными задачами. Сдвиги выбираются по графу передач и цене увеличения ширины, затем все линии прокладываются заново. Человек также подстраивает целую группу под удобные входы и выходы: локальная компактность без хороших интерфейсов недостаточна.

Площадь выросла примерно на 4,9%; это принятый компромисс ради меньшего числа изгибов и лучшего разделения линий. Контакты не уменьшились. До 80 баллов не дошли: маршруты 33,78, расстояния 55,77, контакты 77,30, скученность 81,22, компактность 100, выравнивание 72,39, документы 100. Цель не объявляется достигнутой.

Размещение по нумерации этапов, ELK-слои, ориентация решений и коридоры возвратов проверены отдельно. Ориентация дала 70,91, но добавила патологическое ребро и не принята. Коридоры не дали безопасного улучшения. [Протокол экспериментов](../tests/reports/r6_experiments.json) сохраняет и неудачные варианты. 64 узла, 95 переходов, 18 ассоциаций, 17 документов и 6 ролей сохранены. Все шесть проверок целевого результата прошли; semantic diff и DI diff = 0. Полная печать на одном A4 остаётся слишком мелкой.

## Устойчивость оценки

Leave-one-file-out: медиана 97,785, минимум 29,57, 28/32 файлов ≥80. Это диагностика распределения, а не доказательство точности: тематически близкие процессы зависимы, а некоторые ручные схемы существенно отличаются от большинства.

300 файловых bootstrap-выборок с seed 23: r6 лучше r4 в 300/300. Для r4 p05/медиана/p95 = 40,64/53,60/68,82; для r6 = 51,48/66,745/83,02. Это чувствительность к составу корпуса, не доверительный интервал человеческого сходства. Разброс показывает, почему одного «процента похожести» недостаточно.

## Воспроизведение

```bash
python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn \
  --output-dir experiment-r6 --layout-engine lane-align \
  --incumbent examples/process_08_r4.bpmn --candidate-timeout 120 \
  --reference-profile src/v23/bpmn_v23/assets/reference_conformity_profile.json

# Для новой модели сначала получить проверенную исходную компоновку:
python run_v23.py --input path/to/model.bpmn --output-dir first-layout
python run_v23.py --input path/to/model.bpmn --output-dir aligned-layout \
  --layout-engine lane-align --incumbent first-layout/process_08_v23.bpmn \
  --reference-profile src/v23/bpmn_v23/assets/reference_conformity_profile.json

# Необязательный внешний движок:
npm ci
python run_v23.py --input path/to/model.bpmn --output-dir elk-layout --layout-engine elk

python tools/calibrate_references.py --archive '/path/Готовые процессы.zip' \
  --output calibration --candidate output/process_08_v23.bpmn
python tools/reference_sensitivity.py --report calibration/reference_report.json \
  --baseline examples/process_08_r4.bpmn --candidate output/process_08_v23.bpmn \
  --output sensitivity.json
PYTHONPATH=src/v23:src/v22 python -m pytest tests src/v22/tests -q
```

Все результаты сохраняются отдельно от входов. Адаптеры `author-stages`, `seed-orient`, `route-refine` остаются явными экспериментальными режимами. Ограничение времени A* может влиять на выбранные координаты и маршруты. Исходный r4 сохранён, повторное улучшение может использовать опубликованный r6 как incumbent, чтобы технически допустимый результат не регрессировал по оценке.

Следующая содержательная задача — совместно размещать несколько последовательных шагов вместе с их точками передачи между ролями, а затем переразводить целую группу конфликтующих рёбер. Одно ребро часто нельзя улучшить, пока соседние занимают нужные каналы; увеличение его штрафа не решает эту зависимость.
