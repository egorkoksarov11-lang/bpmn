# Подробное предварительное планирование на базе v23.8

Экспериментальная версия `23.8.2-detailed-plan`. Основная v23.8 сохранена. Полная генерация проверена на четырёх заранее выбранных крупных процессах с 36–42 задачами, 6–9 ролями и 9–22 шлюзами. Входные файлы совпадают по SHA256 с предыдущим сравнением; исходная геометрия стирается до расчёта. Документы одинаково нормализованы до запуска всех версий.

## Что изменилось

- Вместо сравнения прямых между центрами измеряются четыре компоновки: два развернутых порядка прикрепления веток, сложенная полоса участков и сетка цепочек роли. Грубый поиск ширины/высоты по-прежнему рассматривает больше вариантов, но дорогая проверка ограничена четырьмя.
- Порядок ролей пересчитывается по фактическим высотам и положениям концов межролевых связей. Для рассматриваемых 6–9 ролей применяется точная динамическая оптимизация.
- Быстрый пробный проход выбирает до шести ортогональных маршрутов для связи. Проверяются фигуры, подписи и заголовки ролей. У развилок до трёх связанных переходов рассматриваются совместно с шириной поиска два состояния.
- Два лучших по предварительной стоимости варианта проверяются ещё с порядком трассировки «сначала связи с меньшим выбором». Учитываются контакты, общие участки, теснота, длина, изгибы, прямолинейность последовательных задач, площадь и связи документов.
- Не найденный шаблонный маршрут получает штраф; предложения с числом таких связей больше развернутого контроля более чем на два исключаются. Это ограниченность быстрого набора шаблонов, а не доказательство невозможности трассировки.
- Измеренные размещения кешируются. В полную трассировку поступают до двух планов, подсказки путей и порядок связей; существующий исходный конструктор сохраняется. Окончательно доводится один победитель. Финальный маршрутизатор и оптимизатор окон побитово совпадают с v23.8.

Названия и номера шагов не используются для структуры. Текст влияет только через измеряемые размеры. Метаморфные проверки отдельно замораживают измеренную геометрию при подмене текста, проверяют воспроизводимость, неизменность входных данных и независимость от случайно заменённых исходных координат.

### Что ограничивает результат

Новые ранние планы не стали победителями. Изменение набора кандидатов меняет распределение времени поиска; первые два прогона также частично пересекались с проверками. Поэтому суммарные улучшения готовых схем не доказывают преимущество нового планировщика. Относительно предыдущего раннего планировщика результаты тоже смешанные; для замены v23.8 оснований нет.

Быстрый набор шаблонов покрывает только часть связей контрольного плана:

| Процесс | Маршруты найдены быстрым проходом | Доля |
|---|---:|---:|
| large_1 | 65/97 | 67.0% |
| large_2 | 65/104 | 62.5% |
| large_3 | 63/88 | 71.6% |
| large_4 | 51/73 | 69.9% |

Остальные связи передаются полному маршрутизатору, который умеет искать пути вне этих шаблонов. При таком неполном прогнозе предварительная оценка ещё плохо предсказывает итоговую тесноту и контакты. Следующее обоснованное направление — расширить поиск свободных коридоров на измеренном графе препятствий и согласовать порты всего узла, затем проверить точность предсказаний на отдельной когорте. Простое увеличение числа вариантов компоновки само по себе эту проблему не решает.

Ручные эталоны приведены в JSON только как описательная точка сравнения. Процент сходства с человеком этим тестом не установлен. Победитель и статусы всех предложенных ранних планов сохранены в JSON: улучшение при выборе старого конструктора нельзя приписывать новой компоновке.

## Стоимость предварительного анализа

Парный замер выполнен отдельно от полной генерации: один процесс Python, одинаковый вход без DI, прогрев обоих вариантов, три повторения с чередованием порядка. Сравнивается прежний предварительный поиск вместе с материализацией выбранных кандидатов и новый поиск вместе с кешированной материализацией. Чтение XML и финальная трассировка исключены.

| Процесс | Прежняя подготовка, с | Подробная подготовка, с | Отношение |
|---|---:|---:|---:|
| large_1 | 1.035 | 2.646 | 2.56× |
| large_2 | 0.588 | 2.140 | 3.64× |
| large_3 | 0.554 | 1.626 | 2.93× |
| large_4 | 0.513 | 1.443 | 2.81× |

По сумме медиан подготовка стала дороже в 2.92 раза. В одном процессе отношение превышает ориентир 3×: 3.64×. Это цена предварительной подготовки, а не всей генерации.

Времена полной генерации в JSON диагностические: прежние результаты сохранены с прошлых запусков, а новые выполнялись двумя рабочими процессами, частично параллельно с метаморфными проверками. По ним нельзя утверждать ускорение или замедление конвейера.

## Запуск

```bash
python tools/plan_composition.py --input model.bpmn --output plan.json --checks
python run_v23.py --input model.bpmn --output-dir output-new --layout-engine scratch
python tools/benchmark_preplanning.py large1.bpmn large2.bpmn --output timing.json
```

Планировочный JSON содержит измеренные предварительные позиции и пути, но имеет статус `composition_plan_only_not_a_verified_diagram`. Сохранённые пути — подсказки; основной маршрутизатор проверяет их повторно. Первичный проход не заменяет проверки семантики, DI, текста и итоговой геометрии.

## Визуальный просмотр

Просмотрены итоговые SVG large_2 и large_4 вместе с соответствующими ручными эталонами. В large_2 основная последовательность читается слева направо, документы остаются у своих шагов, но справа сохраняется плотный узел возвратов и межролевых линий. В large_4 ручная схема активнее укладывает связанные действия вертикальными группами; автоматическая по-прежнему растягивает основную цепь и соединяет её с удалёнными дорожками длинными вертикалями. Качественного приближения к ручной группировке этот прототип не подтвердил. Изображения изучены локально и не опубликованы.

## Ограничения

Предварительный поиск пока не охватывает произвольные планы схемы: рассматриваются четыре семейства, а локальное совместное решение ограничено тремя переходами. Быстрые шаблоны не находят все пути, доступные полному маршрутизатору. Итоговый старый критерий выбора может отвергнуть лучший предварительный план. Счётчик контактов сам по себе не измеряет удобство чтения; для оценки нужны также длины, последовательность, теснота, документы и визуальный просмотр. Эта ветка экспериментальная и автоматически не заменяет v23.8.
