# Разработка r3 — баланс компактности и читаемости

Статус: экспериментальная версия 23.1.2.dev0. Дата: 1 ноября 2026. Источник бизнес-логики — frozen v4. Новая схема не объявляется окончательным человеческим эталоном.

## Что реализовано

1. Четыре ориентации пары «задача — шлюз» с оценкой всех связей обоих узлов.
2. Согласованное увеличение высоты ряда, перенос последующих рядов, дорожек и документных областей.
3. Ограничение ухудшения пропорций по p10 измеренных человеческих референсов.
4. Опциональный повторно проверяемый incumbent — исходная хорошая геометрия того же frozen графа. Ошибки семантики, DI или маршрутов приводят к отклонению incumbent.
5. После уточнения пользователя — balanced-readability-v1: пучки, локальная плотность, длинные переходы, контакты, изгибы и чрезмерная площадь.
6. Human-маршрутизатор штрафует близкие параллельные участки и пересматривает такие линии даже без пересечений. Пространственный индекс ограничивает перебор соседних сегментов; независимые проверки сохранены.

## Сравнение последнего результата с r2

Одинаковая frozen-модель, одинаковые задачи 220×80 и шрифт 13 px. Прежняя геометрия доступна в examples/process_08_r2.bpmn и previews/human-patterns-r2.

| Метрика | r2 | r3 balanced |
|---|---:|---:|
| Семантических изменений | 0 | 0 |
| Контактов/пересечений | 49 | 60 |
| Изгибов всех связей | 178 | 200 |
| Индекс близких параллельных участков | 0.464144 | 0.035540 |
| Избыточная локальная плотность | 0.168183 | 0.065178 |
| Максимум потоков в диагностической ячейке | 9 | 8 |
| Длинных прямых по графу переходов, без обратных рёбер | 40 | 33 |
| Тяжесть длинных переходов, с меньшим весом возвратов | 1.212540 | 1.361593 |
| Полный габарит DI | 2962×2105 | 2957.5×2181.0 |

«Прямых по графу» в строке о переходах означает обычное продолжение, а не прямой отрезок на рисунке. Длинным считается маршрут свыше двух медианных ширин задачи. Возвраты определяются по доминированию, а не по направлению влево. Индекс пучков учитывает протяжённость и расстояние между параллельными линиями. Порог близости — 0,15 высоты задачи, здесь 12 DI; из расчёта плотности исключены короткие терминальные участки у фигур.

По диагностике близких параллельных участков снижение 92.3%, площадь выросла на 3.45%. Это не означает «читаемость выросла на 92.3%»: субъективная оценка пользователем не проводилась. Длинных переходов стало меньше, но суммарная тяжесть оставшихся выросла примерно на 12.3%. Контактов и изгибов стало больше. Это открытый компромисс, а не улучшение всех показателей сразу.

Остался один маршрут с более чем восемью изгибами: F83. Он отражён в геометрическом отчёте. Наложений фигур, общих наложенных сегментов, проходов через посторонние фигуры, нарушений 8 DI clearance, обрезанного текста и коллизий подписей у выбранной схемы не найдено.

## Ход эксперимента

- Без ограничения высоты: выбран вариант с 50 контактами, 169 изгибами и габаритом 2957,5×2485. Не принят как замена r2: площадь существенно выросла.
- С ограничением пропорций и проверенным incumbent: исходный r2 с 49 контактами сохранён, новые варианты по прежней функции не выиграли.
- После указания пользователя о пучках и непрерывности чтения: изменены глобальный критерий выбора и локальная политика маршрутизатора. Последний эксперимент включал incumbent и четыре ориентированных предложения. Три предложения отклонены жёсткими проверками; выбран допустимый вариант с последующей доводкой маршрутов.

Выбран `human-blocks-2-secondary-2-oriented-refined`. Длительность backend-прогона — 303.45 с; бюджет 120 с на кандидат. Режим эксперимента `--orientations-only` не перебирал четыре обычных базовых размещения заново. Обычный CLI без этой опции сохраняет полный перебор базовых и ориентированных вариантов. Различия времени A* могут влиять на завершённость и координаты результата.

- Semantic diff = 0; проверена неизменность DI-структуры и повторное открытие сохранённого XML/SVG.
- Два дополнительных процесса HR12/HR13 повторно скомпонованы текущим backend: оба прошли проверки, semantic diff = 0. Пропорции A4 у них не достигнуты; это не скрывается.

## Запуск сравнительного эксперимента

```bash
python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn \
  --output-dir output-r3 --candidate-timeout 120 \
  --incumbent examples/process_08_r2.bpmn --orientations-only
PYTHONPATH=src/v23:src/v22 python -m pytest tests src/v22/tests -q
```

Для нового процесса incumbent не нужен: убрать --incumbent и --orientations-only. Для сравнения без поворотов решений — --no-decision-orientations. Результаты сохранять отдельно от входных файлов.

## Оставшиеся ограничения

Результат остаётся экспериментальным. Пороговые значения и веса — инженерная политика, а не обученные предпочтения пользователя. Локальные метрики могут расходиться с визуальной оценкой. Пересечения остаются, глобальная оптимальность не доказана. При печати всей схемы на одном A4 минимальный шрифт оценивается в 2.96 pt; это слишком мелко, несмотря на подходящее отношение сторон.

Для дальнейшего сокращения скачков чтения нужно совместное размещение целых проверок/согласований и основных шагов. Пока display backbone не перепаковывается целиком; графовый анализатор сложных сценариев остаётся отдельным инструментом. Модель бизнес-процесса, роли, документы и связи при этом должны оставаться неизменными.
