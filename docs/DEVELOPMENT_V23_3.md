# v23.3 — совместное планирование соседних шагов и линий

Генератор дополняет построение с нуля проходом по перекрывающимся окнам A→B→C. A закреплён; положение B и C и обе внутренние линии выбираются совместно. Это ограниченный поиск с просмотром на два перехода, а не имитация действий мыши или доказанный оптимальный алгоритм. Координаты ручных примеров не используются при построении.

## Что подтверждено наблюдениями

Проанализированы 59 сохранённых состояний четырёх сессий, 55 переходов между сохранениями. В 544 изменённых перекрывающихся окнах обнаружены 337 совместных относительных перемещений B/C и 391 случай изменения обеих линий. Общий перенос всей схемы вычитается. Это наблюдения окон, а не число независимых действий автора: одно движение затрагивает несколько окон. Между сохранениями встречаются изменения бизнес-XML; анализ геометрии использует только окна с неизменными связями, видами узлов и ролями.

Человек не минимизирует каждый показатель отдельно. В ручных примерах бывают развороты, более далёкие шаги запроса/ответа и локальное увеличение числа поворотов. За это нельзя автоматически штрафовать. Полезнее совместно оценивать простоту двух соседних связей, длину, свободное место и последствия для границ фрагмента. В ручных финалах доля простых окон вокруг последовательной задачи: S1 70%, S2 88,5%, S3 75%, S4 83,3%; у v23.2: 65%, 42,3%, 65%, 55,6%.

Отдельный наблюдаемый паттерн — операция, затем решение над/под ней, затем передача в другую роль. Горизонтальная операция со шлюзом иногда требует лишних изгибов перед передачей. Вертикальный вариант добавлен как предложение, а не обязательное правило.

## Поэтапный поиск

- Из бизнес-графа выделяются окна с исключением обнаруженных обратных дуг. Разветвления учитываются; пары около одного шлюза имеют суммарный вес 1.
- Выбирается ограниченный набор проблемных окон, затем обходится по расстоянию от начала процесса. Это проход по уже автоматически построенному черновику; префикс всего бизнес-графа не замораживается.
- Проверяются горизонталь, вертикаль, угол, запрос/ответ, вертикальный шлюз перед межролевой передачей, смещения на 20 px и замена только линий.
- Обе внутренние линии прокладываются в двух порядках; beam search сохраняет до трёх альтернатив. Выбираются стороны и смещённые порты, прямые и ортогональные короткие пути. При отборе промежуточных маршрутов учитываются контакты.
- Все связи с остальной схемой переподключаются и включаются в оценку. Учитываются занятые порты и существующие линии. Документ перемещается с операцией; значок и измеренная подпись размещаются общим блоком, вне предполагаемого прямого перехода.
- Каждый кандидат повторно открывается из XML и проходит семантическую, DI, геометрическую и текстовую проверки. Непригодные предложения отбрасываются. Сохраняется лучший полностью проверенный префикс прохода; при отсутствии выигрыша остаётся исходный автоматический черновик.

Окна перекрываются: следующий фрагмент может поправить предыдущий шаг просмотра вперёд. Общий бюджет по умолчанию до 45 секунд; дополнительный лимит на окно не даёт первому сложному участку поглотить весь поиск. Внутренняя отдельная операция и обязательная полная проверка могут закончиться позднее мягкого бюджета.

## Метрики и ограничения

Корректность задаётся независимыми обязательными проверками: полное бизнес-XML, принадлежность ролям, условия, все документы и связи; DI-идентичность; отсутствие проходов через фигуры, совпадений линий, обрезанного текста и конфликтов подписей. Это отдельные требования, а не часть среднего балла.

В `geometry_report.json` добавлен `window_readability`:

| Показатель | Что измеряет / ограничение |
|---|---|
| `simple_window_fraction` | Доля окон вокруг последовательной задачи, обе связи имеют ≤1 физического поворота |
| `weighted_simple_window_fraction` | То же для всех окон, с равным суммарным весом около каждого центрального узла |
| `excess_wire_mean_task_units`, `excess_wire_p90_task_units` | Длина сверх минимального расстояния между прямоугольниками, в фиксированных единицах 200 px; это включает стоимость выбора портов, не только устранимый обход |
| `short_internal_jogs` | Внутренние сегменты короче 12 px, кроме первого и последнего |
| `tight_parallel_pairs`, `parallel_pressure_fixed_units` | Близкие параллельные линии и протяжённость их соседства при пороге 12 px |
| `contact_types` | Контакты управление/управление, управление/документ, документ/документ; семантически общий терминал исключён |
| `long_flow_count`, `flow_length_p90_task_units` | Число связей длиннее 600 px и хвост распределения длин |
| `serial_hairpins`, `request_reply_*` | Контекст направления и запроса/ответа. Не ошибки и не цели минимизации |

Повороты считаются по изменению направления ненулевых сегментов; добавление точек на прямой не улучшает оценку. Контакты — пересечения и неоднозначные касания, а не нарушения бизнес-логики. Площадь, длины, доли прямых связей и расстояния документов остаются в комплексном отчёте. Раздувание размеров задач не вознаграждается: новые показатели используют фиксированные физические единицы. Шрифт и полный текст проверяются отдельно.

Внутренний локальный балл: 1,5 за поворот + длина/200 для двух линий. Отбор маршрутов учитывает 8 за контакт. Это инженерные веса; процент сходства с человеком из них не выводится. Локальный проход не увеличивает контакты и число поворотов; рост общей длины до 1% допускается при другом подтверждённом выигрыше. Сохраняется явный компромисс, а не обещание улучшить каждый показатель.

Текущий поиск консервативен: фиксированные полосы ролей и окружение могут не позволить хороший перенос. Конечный набор прямых/L/Z-маршрутов может пропустить полезный дальний обход. Три шага не заменяют глобального переустройства нескольких веток. Корпус из четырёх сессий используется для разработки, не является независимым тестом обобщения. Уровень ручных референсов и 80% визуального сходства не заявляются.

## Защитный выбор целой компоновки

Испытание S2 показало риск обратной ошибки: меньше поворотов, но заметно больше контактов, длины и площади. Дополнительный графовый конструктор теперь проверяется при сочетании более 1,2 поворота на поток, более 0,5 контакта на поток и средней длины более 500 px (раньше 600 px). Он также строится заново по удалённой входной геометрии.

Добавлен ограниченный компромисс между целыми компоновками: контактов минимум на 20% меньше, число поворотов может вырасти максимум на 20%, длина максимум на 5%, площадь максимум на 10%, а балл `8×контакты + 1,2×повороты + длина/200` должен улучшиться минимум на 7%. Прежние варианты Парето и существенного выигрыша компактности сохранены. Такой выбор журналируется как `bounded_wire_readability_trade`; это отдельная политика от более строгого локального прохода. Все обязательные проверки остаются обязательными.

## Воспроизведение

```bash
npm ci
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/prepare_observation_benchmark.py \
  --archive /path/to/bpmn_observations.zip --output-dir private-inputs
.venv/bin/python tools/benchmark_four_processes.py \
  --input-dir private-inputs --output-dir private-results \
  --candidate-timeout 60 --search-seconds 200

# Отдельный дополнительный проход; исходные модели не перезаписываются.
.venv/bin/python tools/refine_generated_windows.py \
  --input-dir private-inputs --results-dir private-results --seconds 45 --recheck-cold-guard

# Повторный аудит финальных файлов после отдельного прохода.
.venv/bin/python tools/benchmark_four_processes.py \
  --input-dir private-inputs --output-dir private-results --audit-only
.venv/bin/python tools/package_four_results.py \
  --inputs private-inputs --results private-results --output-dir private-gallery

# Анализ собственных распакованных записей, отдельно от генерации.
.venv/bin/python tools/analyze_window_patterns.py \
  --observations /path/to/bpmn_observations --output human-window-patterns.json
PYTHONPATH=src/v23:src/v22 .venv/bin/python -m pytest tests src/v22/tests -q
```

Один процесс: `python run_v23.py --input model.bpmn --output-dir result --candidate-timeout 60 --search-seconds 200`. Обычный запуск уже содержит один проход окон; дополнительная команда выполняет ещё один. Для контроля только нового этапа есть `--skip-staged-windows`. Имена выходов `process_08_v23.bpmn/.svg` сохранены ради совместимости; процессы разделяются каталогами.
