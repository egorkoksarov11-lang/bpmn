# Генератор 23.6.0: блоки, трассы и стабильная финализация

Новая версия строит схему с нуля по связям, типам BPMN и принадлежности ролям. Исходная DI-геометрия удаляется до выбора размещения. Названия и номера не определяют структуру; текст измеряется для реальных размеров объектов и подписей.

## Реализованные изменения

1. **Связанные блоки вместо независимых шагов.** Граф делится на группы до восьми узлов: развилки с объединениями, циклы, локальные цепочки роли. Добавлены кандидаты с двумя/тремя колонками и вертикальными парами. Поиск сохраняет прежние разнообразные стартовые семейства. Новый кандидат принимается только после маршрутизации и проверки всего результата.
2. **Совместное сжатие объектов, подписей, портов и ортогональных трасс.** HiGHS решает линейную задачу по X-координатам. Высоты, Y-координаты, размеры объектов, вертикальные отрезки, смещения портов и порядок существующих пересечений зафиксированы. Ограничения учитывают реальные подписи, документы, заголовки дорожек и минимальные промежутки. После решения выполняется независимая геометрическая проверка; любое ухудшение безопасности отклоняется. Проход уменьшает свободные интервалы, но сам по себе не устраняет существующие пересечения.
3. **Атомарное локальное редактирование и стабильный выпуск.** Для блока совместно перебираются размещения и варианты портов/маршрутов. Узлы, трассы и подписи вне области изменения закреплены; дорожки не расталкиваются. Неподходящая попытка откатывается целиком. В финале нормализация подписей должна достичь неподвижной точки: повторный проход не меняет геометрию. Это проверяет стабильность генератора; поведение стороннего редактора после ручной правки он не гарантирует.

Некоторые новые блочные варианты уступают старым, поэтому сам факт их появления не означает их выбора. В первом эксперименте дополнительный штраф за площадь/контакты и сокращение прежнего уточнения до 40 секунд дали регрессии. Эти настройки не включены в итоговую версию: возвращены прежняя оценка кандидатов и прежний лимит уточнения 100 секунд. Новый атомарный проход получает до 30 дополнительных секунд. Это осознанное увеличение завершающего бюджета, а не доказательство ускорения.

## Сопоставление версий

Тестовая база — неизменная копия 23.5.1. Четыре входа подготовлены из присланных наблюдений. Документы, удалённые в ручной финальной версии, удалены **до обоих запусков**, вместе с их связями. Счётчики документов: 20→16, 4→3, 6→6, 8→2. Хеши одинаковых входов сохранены в отчёте. Ручные координаты не передаются генератору.

Общие параметры: `scratch`, `--candidate-timeout 60`, `--search-seconds 200`. Это лимиты кандидата и основного поиска, а не полного времени выполнения. База запускалась последовательно; новая версия — двумя процессами, каждый закреплён на одном CPU. Нагрузка и таймеры могут менять набор успевших кандидатов. Времена приведены только как диагностика; выводов об ускорении нет. Финальный дополнительный локальный проход имеет отдельный лимит до 30 секунд.

Площадь измеряется по видимым объектам, подписям и линиям, без пустых рамок пулов. Длина — сумма последовательных потоков. «Контакты» — счётчик неоднозначных пересечений/касания по независимому аудиту; это шире обычного числа пересечений. Разбивка по процессам и агрегаты публикуются отдельно. Совпадение с ручной схемой на 80% этим тестом не установлено.

Результаты заполняются после окончания финальных прогонов. Исходные записи и бизнес-схемы в публичный ZIP не включаются.

## Самостоятельный запуск

Windows: распаковать ZIP и открыть `START_WINDOWS.cmd`. Установка зависимостей выполняется автоматически. JSON/YAML и совместная схема с двумя процессами продолжают использовать тот же входной адаптер.

Для CLI нужны Python ≥3.11, Node.js и зависимости из `requirements.txt`; добавлены NumPy и SciPy с HiGHS. Windows x64 проверяется в GitHub Actions; Windows ARM64 имеет отдельный выбор wheel NumPy, но на физическом ARM64 запуск не подтверждён.
