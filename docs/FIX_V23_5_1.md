# v23.5.1 — ложный отказ collaboration_geometry_rejected

Ошибка общей проверки: для подписи возле ромба/эллипса использовалось пересечение с прямоугольником вокруг фигуры. Пустые углы прямоугольника ошибочно считались занятой частью ромба/эллипса. Та же подпись уже проходила проверку отдельного процесса по настоящему контуру, но общая collaboration могла её отклонить.

Исправление использует общий с проверкой процесса `label_hits_shape` и исключает служебные label-bounds внутренних подписей задач, как делает обычный аудит. Настоящее пересечение подписи с фигурой по-прежнему отклоняется. Бизнес-XML, IDs, связи и сами маршруты от этого исправления не меняются.

Сообщение об отказе больше не начинается с огромного списка успешных метрик. Оно перечисляет проваленные проверки с ID объектов. Полный отчёт сохраняется в `output/geometry_error.json`; интерфейс предлагает скачать его вместе с журналом. Непроверенный BPMN/SVG в случае отказа не предлагается.

Проверен приложенный пользователем JSON: исходная структура и ссылки корректны. В старом аудите обнаружены две ложные пары «подпись/ромб», при этом маршрутизация, зазоры, концы сообщений, пулы и прохождение линий через подписи были корректны. Исправленный аудит принимает тот же кандидат; полное бизнес-XML и структура DI совпадают с входным BPMN, SVG отрисовывается. Приватный вход и его результат в публичный репозиторий не включены.

Регрессии: пустой угол ромба и эллипса разрешён, фактическое наложение на их внутреннюю часть отклоняется; диагностический JSON доступен после ошибки, а непроверенная схема недоступна. Пересечения линий остаются отдельной мягкой метрикой и сами по себе не являются причиной этого отказа.
