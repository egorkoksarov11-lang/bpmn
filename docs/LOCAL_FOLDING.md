# Локальные вертикальные блоки: промежуточная v3

Схема №4 v2 имела длинную горизонтальную магистраль. Новый режим собирает короткие связанные операции в вертикальные пары, затем решает ограничения расстояний по реально занятым прямоугольникам. Шрифт, размеры задач и полный текст сохраняются. Документы и подписи остаются при владельце и выводятся за пределы соединителя внутри пары.

`--local-fold --fold-kind tasks` складывает последовательные операции. `hybrid` добавляет короткие пары «операция — проверка» во второстепенных ролях; `all` рассматривает более широкое складывание решений и служит экспериментальным вариантом. Главная роль определяется по числу операций. Для пар требуется существующий переход; разветвление не превращается в безусловную цепочку. В гибридном режиме допускается укладка операции и следующего объединяющего шага с сохранением всех входов.

После укладки удаляются незанятые интервалы между колонками и рядами. Для именованных вертикальных переходов резервируется измеренная подпись до трассировки. При перестановке роли подпись движется вместе с ней. Для части длинных названий ветвей сохраняется дополнительное место. Все маршруты строятся заново и независимо проверяются.

Это геометрическое преобразование: semantic diff = 0 относительно v2; все 69 узлов, 86 переходов, 17 информационных объектов и 17 связей сохранены. Порядок ролей фиксирован как в v2. Исходные координаты не используются: упаковка применяется к заново сгенерированным положениям.

| Показатель | v2 | Предварительная v3 |
|---|---:|---:|
| Ширина | 6834,10 | 4871,26 |
| Высота | 2534,35 | 1990,00 |
| Площадь | 17 320 001,34 | 9 693 807,40 |
| Контакты линий | 16 | 12 |
| Длина sequenceFlow | 40 542,55 | 35 848,66 |
| Изгибы sequenceFlow | 77 | 116 |

Ширина уменьшена на 28,7%, высота на 21,5%, площадь примерно на 44%, длина линий на 11,6%. Рост числа изгибов остаётся ограничением; качество ручных эталонов и A4 не заявляются. Агрессивное складывание всех решений дало ширину около 3440, но увеличило длину линий до 68 612 и контакты до 40; этот результат не выбран. Более умеренный вариант только операций уменьшает изгибы относительно гибридного, но остаётся шире. Данные вариантов сохранены в `tests/reports/process04_v3_comparison.json`.

147 тестов прошли за 42,33 секунды. Новые проверки покрывают неизменность размеров и состава объектов, свободный вертикальный соединитель, сохранение ветвления и дополнительных входов, подписи BPMNEdge и их перемещение с ролью. Опубликованный ZIP скачан обратно, CRC и все SHA256 проверены. Исходные и подготовительные модели исключены из публичного пакета.

## Воспроизведение

Возьмите собственный BPMN v2 и выполните после установки зависимостей:

```bash
python tools/compact_process.py --input path/to/v2.bpmn --output-dir preview --local-fold --fold-kind hybrid --spacing-factors 1 --role-order L_Op L_UL L_Cash L_FH L_CM L_Factor L_Client L_Acc L_HR --candidate-timeout 45 --search-seconds 45
```

Для другого процесса задайте `--role-order auto` или его ID ролей. Для строгой компоновки без новой документной проекции используется основной `run_v23.py`. Корпусные показатели r10 не пересчитывались для этого режима.
