# Раннее планирование на базе v23.8: реализация и апробация

Базовая v23.8 сохранена отдельно. Прототип `23.8.1-preplan-r3` добавляет начальный план перед координатами и трассировкой. Он не использует две полные доводки v23.9. Маршрутизатор `router.py` и оптимизатор линий `window_planner.py` побитово совпадают с v23.8; существующий интерфейс подсказок применяется к возвратным линиям нового плана. Уточняется один выбранный безопасный кандидат.

## Что реализовано

- Разбор связей на последовательные участки, основную графовую последовательность, прикреплённые ветки и возвраты.
- Два семейства композиций: сетка цепочек роли с короткими поворотами и согласованные полосы целых участков с межролевыми передачами. Рассматривается и развернутый вариант без сворачивания.
- Выбор ширины рядов, роста высоты дорожек и порядка ролей. Для 6–9 ролей применяется точное подмножественное динамическое программирование к оценке взаимодействий с учётом высот.
- Логические документы группируются по явной идентичности `dataObjectRef`, уже сохранённой парсером; названия для поиска зависимостей не используются.
- Дешёвая оценка площади, длины переходов, больших прыжков, пересечений и информационных зависимостей. Предварительный ограничитель сравнивает предложения с развернутым контрольным планом.
- До двух прошедших предварительный выбор предложений передаются существующему конвейеру v23.8. Проверенный исходный конструктор остаётся кандидатом. Все выданные результаты проходят прежние проверки семантики, текста и геометрии.

Предварительные пороги — инженерные эвристики: оценка пересечений не выше `max(control+2, control×1.2)`, площадь не выше `control×1.25`, оценка стоимости не выше `control×1.1`. Они не калиброваны как гарантия качества. Грубые пересечения по центрам и фактические неоднозначные контакты после ортогональной трассировки — разные меры. Их нельзя отождествлять.

## Быстрый самостоятельный анализ

```bash
python tools/plan_composition.py --input model.bpmn --output plan.json
```

Команда не прокладывает линии и не меняет исходник. JSON содержит `analysis`, массив `plans`, порядок ролей `role_order`, число рядов `rows`, позиции узлов `slots`, параметры ширины и оценки рисков. Результат имеет статус `composition_plan_only_not_a_verified_diagram`.

`columns` — верхний предел позиций в ряду, а не число операций в процессе. Для контрольного развернутого режима используется предел по числу узлов; фактическая ширина определяется занятыми позициями и размерами элементов. Полный текст измеряется при канонизации и размещении подписей. Структурный поиск не читает смысл текста или номера шагов.

## Полная генерация: сравнение с v23.8

Четыре процесса выбраны заранее: 36–42 операции, 6–9 ролей, 9–22 шлюза. В обоих вариантах одни и те же входные SHA256. Документы из финальных ручных снимков уже приведены к их последнему составу. Исходные координаты стираются. Контрольные результаты v23.8 сохранены из предыдущего испытания; их время не является контролируемым измерением ускорения нового кода. Бюджеты — кандидат 60 с, начальный поиск 200 с, аварийный предел запуска 1800 с, `PYTHONHASHSEED=0`.

Успешные выдачи: v23.8 — 4/4, прототип — 4/4. Название выбранного кандидата указывает исходную конструкцию; последующие геометрические уточнения могут её изменить. Новые планы стали начальной победившей конструкцией в 1 из четырёх случаев.

Численные изменения всей версии нельзя автоматически приписывать качеству новых планов. Их добавление меняет очередь кандидатов при том же бюджете поиска; даже при выборе резервного конструктора итог может отличаться от сохранённого контроля. JSON содержит статусы каждого нового предложения и сведения о резервной компоновке.

## Что выяснили в ходе разработки

Первый пилот на двух наиболее сложных процессах: все четыре новых сеточных предложения превысили 60 секунд трассировки. После расширения коридоров некоторые варианты стали проходимыми, но на №4 получили 130 и 212 контактов и чрезмерные изгибы. Во втором полном опыте на четырёх процессах ни один сеточный план не стал победителем.

Финальный прототип сравнивает сетки и согласованные полосы участков с развернутым контролем. На текущей выборке предварительный ограничитель исключил сильное глобальное сворачивание. Это не доказательство невозможности компактной ручной схемы: показатель риска грубый и может отвергать хорошие варианты. Быстро разобрать граф удалось; достоверно предсказать удобные коридоры и порядок портов только по дешёвой оценке пока не удалось.

## Проверки и пределы результата

Выданные BPMN повторно прочитаны и сравнены с исходниками: бизнес-XML, DI-идентичность, маршруты, просветы от фигур, подписи и переполнение текста. Входные SHA256 и исходники алгоритма оставались неизменными во время окончательных четырёх прогонов. Малые схемы для оценки качества не использовались.

Полная генерация по-прежнему занимает минуты. Подтверждена скорость отдельного начального анализа; качество ручной сборки и генерация без ручной доводки не заявляются. До дальнейшей проверки качество-предсказателя прототип остаётся в отдельной ветке, исходная v23.8 не заменяется.

Подробные данные: `tests/reports/early_plan_v23_8/comparison.json`, `comparison.csv`, `planning_checks.json`, `provenance.json`. Приватные BPMN и записи ручной работы не публикуются.

## Итог апробации

Новый план стал победителем на одном процессе из четырёх — ФНС. Там площадь −9,72%, длина потоков −13,40%, изгибы 107 → 85 и прямые последовательные связи 8/11 → 9/11. При этом контакты 14 → 16, мера сближения параллельных линий 0,01918 → 0,03957, максимальный переход по порядку ролей 3 → 4 дорожки. Физический максимальный вертикальный разрыв между взаимодействующими узлами также вырос: 897 → 945 единиц DI. Это компромисс, а не безусловно лучшая читаемость.

На №4 результат совпал с базой. На №08 резервная компоновка дала меньшую площадь и длину линий ценой дополнительных контактов. На реестре резервный вариант ухудшился: площадь +10,11%, линии +8,34%, прямые последовательные связи 13/15 → 12/15.

По сумме четырёх процессов: площадь −3,86%, потоки −11,79%, изгибы −7,16%, контакты +8,49%. Статус успешной геометрии и семантики — 4/4 у обеих версий. Ни один свёрнутый план не стал победителем: на этом наборе скорый анализ предпочёл развернутые формы. Полезность автоматического сворачивания до уровня ручных референсов пока не подтверждена.

Следующий необходимый шаг — оценка исполняемости коридоров и порядка портов до подробной трассировки, а также пересчёт порядка ролей по фактическим измеренным высотам. Увеличивать число сеточных вариантов без этого не оправдано. Быстрый аналитический этап реализован; заменять им исходную v23.8 по результатам этой апробации пока рано.

После окончательных прогонов исправлен отдельный случай удаления дублирующего контрольного плана: развернутый контроль сохраняется, даже если его геометрия совпадает с предыдущим вариантом. На всех четырёх крупных входах планы до/после исправления совпали; отдельно проверено принудительное совпадение предложений на крупном графе. Источник, использованный для полной генерации, и опубликованный источник отражены отдельными SHA256 в provenance. Эта совместимость не меняет арифметику компоновки проверенной выборки.
