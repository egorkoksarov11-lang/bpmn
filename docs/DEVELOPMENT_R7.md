# r7 — прямые связи между соседними шагами

Основание — обратная связь пользователя: рядом расположенные последовательные операции должны читаться подряд, без лишних изгибов. Эталон — реальные ручные схемы. Только геометрия BPMN-DI, semantic freeze и DI freeze обязательны.

## Что обнаружено в референсах

Повторно измерены 32 ручных процесса. Для диагностики близкой считаем непосредственную связь sequenceFlow с манхэттенским расстоянием между границами фигур не более 0,8 медианной ширины задачи. Порог нормирован по размеру задач и не использует ID/названия процесса №08. Он является инженерным определением, а не доказанным порогом человеческого восприятия.

Из 566 таких связей 448 прямые, 84 с одним изгибом, 34 с двумя и более. Общий процент недостаточен: пары задача→шлюз могут скрыть плохое подключение следующих шагов.

| Тип близкой связи | Ручные референсы | №08 r6 | №08 r7 |
|---|---:|---:|---:|
| Задача → шлюз, прямые | 105/138 = 76,1% | 21/21 | 21/21 |
| Шлюз → задача, прямые | 99/141 = 70,2% | 7/12 = 58,3% | 8/12 = 66,7% |
| Задача → задача, прямые | 123/142 = 86,6% | 4/4 | 4/4 |
| Все близкие связи, прямые | 448/566 = 79,2% | 33/38 = 86,8% | 34/38 = 89,5% |

Таким образом, проблема прежде всего в выходах из развилок, хотя общий процент r6 уже выше среднего по корпусу. Сравнение не контролирует различия сложности процессов и не является человеческой оценкой сходства. [Полные измерения](../tests/reports/r7_reference_continuity.json).

Ручной принцип, который воспроизводит новый этап: сначала согласовать положение соседних фигур и сторон подключения, затем провести короткую связь; учитывать остальные входы и выходы сдвигаемой фигуры. Жёсткая постановка каждого шлюза справа от задачи не гарантирует удобного продолжения ветки.

## Изменение алгоритма

Новый режим `local-continuity` улучшает проверенную исходную компоновку. Поиск охватывает непосредственно связанные фигуры с расстоянием до одной ширины задачи. Отдельная контрольная метрика выше использует более узкий радиус 0,8. ID обоих наборов фиксируются до поиска: удаление плохой связи из геометрической окрестности не улучшает оценку.

1. Проверяет подключения с соседних сторон: например, снизу шлюза в правую сторону задачи может хватать одного изгиба. Набор простых маршрутов прежнего роутера преимущественно связывал противоположные стороны; A* мог найти другие подключения, но запускался не для каждой допустимой конфликтующей связи.
2. Пробует небольшие горизонтальные/вертикальные сдвиги одного или обоих концов связи, чтобы появилась общая ось. Задача может сдвигаться вместе с документами, а её шлюз — сохранять короткий прямой зазор вместо обязательного жёсткого сдвига всей пары.
3. Сохраняет непричастные линии; заново прокладывает связи сдвинутых объектов и линии, которым они перекрыли путь. Новую короткую связь резервирует до трассировки остальных.
4. При добавленных контактах пробует повторно развести небольшой набор конфликтующих рёбер, включая A*. Защищённые линии не изменяются.
5. Принимает только результат без увеличения контактов, общего числа изгибов и общей длины относительно incumbent. Существующие прямые связи в контрольной окрестности запрещено ухудшать. Каждое принятое изменение проходит полный аудит сохранённого файла: фигуры, маршруты, зазоры, подписи, текст, семантика и структура DI.

При исчерпании времени сохраняется лучший уже проверенный вариант, а не незавершённая попытка. Повторный запуск не гарантирует глобального оптимума. Основные предыдущие режимы не меняют политику выбора; новый этап включается явно.

## Измеримый результат

На №08 исправлена связь после проверки изменения условий исполнения: теперь она идёт прямо вместо двух изгибов. Сохранены все ранее прямые близкие связи. Близкие связи с двумя и более изгибами: **4 → 3**; изгибы в фиксированной контрольной окрестности: **10 → 8**. Общее число изгибов: **151 → 149**, контакты **40 → 40**, суммарная длина **49 858,3 → 49 779,3**. Значимого увеличения схемы нет. Балл неизменённого профиля семи семейств: **70,39 → 71,16**. Порог 80 и формула r6 не менялись; цель 80 по-прежнему не достигнута.

Выигрыш локальный. Остальные предложения часто выпрямляют нужную связь, но добавляют пересечения соседних линий; они отклонены. В итоговой контрольной группе остаются три связи с несколькими изгибами и одна с одним. Это открытые ограничения, а не объявленные неизбежными пересечения. Одно лишь принудительное выпрямление любой ценой ухудшает чтение окружающего участка.

Семантика, 64 узла, 95 sequenceFlow, 18 ассоциаций, 17 документов и 6 ролей сохранены. Semantic diff и DI diff равны нулю. Нет проходов через фигуры, наложений линий, диагоналей, потерянных подписей и рёбер с более чем 8 изгибами. Умещение всей схемы на одном читаемом A4 не достигнуто.

87 тестов прошли. Новые проверки покрывают подключения с соседних сторон, неизменный набор оцениваемых соседей, совместные сдвиги, сохранность фиксированных маршрутов, отказ от небезопасного фиксированного пути, защиту линий при повторной трассировке и полный проход от XML до проверенной прямой связи без изменения логики.

## Запуск

```bash
python run_v23.py --input inputs/benchmark/process_08_v4_frozen.bpmn \
  --output-dir experiment-r7 --layout-engine local-continuity \
  --incumbent examples/process_08_r6.bpmn --candidate-timeout 120 \
  --reference-profile src/v23/bpmn_v23/assets/reference_conformity_profile.json

python tools/measure_continuity.py --archive '/path/Готовые процессы.zip' \
  --baseline examples/process_08_r6.bpmn --candidate output/process_08_v23.bpmn \
  --output continuity-report.json

PYTHONPATH=src/v23:src/v22 python -m pytest tests src/v22/tests -q
```

Для другого процесса сначала получить проверенную исходную компоновку обычным запуском, затем передать её как `--incumbent`. Архив референсов нужен только для повторного измерения, не для работы нового backend. Node не требуется. Входные файлы и v22 не перезаписываются.
