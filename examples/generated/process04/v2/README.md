# Схема №4 v2 — близкие роли и первые появления документов

Откройте `4_v2.bpmn` в BPMN-редакторе или `4_v2.svg` в браузере. Полный исходник и подготовленная модель сохранены локально. Публичный пакет содержит только сформированную схему и отчёты; исходный XML удалённых элементов из публичного журнала исключён.

Сохранены все 69 узлов процесса, 86 переходов и 9 ролей. Информационные объекты: 18 → 17; их связи: 71 → 17. Каждый оставшийся объект связан только с одной операцией, все 17 связей прямые. Удалён один повторный значок переданных реквизитов; 54 повторных связи исключены из представления. Разные документы и их состояния не объединяются по похожему названию; определения логических данных сохранены.

Порядок ролей сверху вниз:
1. Операционист
2. Уполномоченное лицо
3. Касса
4. Руководитель финансового блока
5. Клиентский менеджер
6. Факторинговая компания
7. Клиент
8. Главный бухгалтер / бухгалтерия
9. Кадровик / HR

Клиентский менеджер находится между двумя наиболее взаимодействующими ролями. Перестановка рассчитана точным динамическим программированием по реальным вертикальным положениям межролевых концов переходов.

45 межролевых маршрутов: суммарная длина 66 670,6 → 29 737,65 (−55,4%), максимальная 3 180,2 → 1 602,85. Все sequenceFlow: длина 80 338,8 → 40 542,55. Контакты линий по общему аудиту: 204 → 16. Улучшение связано с совместным изменением порядка ролей, документного представления и компоновки; это не изолированный эффект одной перестановки.

Исходный business-XML отличается только явно перечисленными удалениями dataObjectReference/associations в `document_changes.json`. После подготовки этой проекции semantic diff = 0; именно к подготовленной модели относится `semantic_diff.json`. Операции, типы, имена, исполнители, условия, переходы и определения данных сохранены. Исходник не перезаписан. 139 тестов прошли; XML, ссылки, полный видимый текст, порты, зазоры, подписи и предел изгибов проверены. Пересечения линий между собой остаются возможными; A4 и универсальное сходство с ручными эталонами не заявляются.

Воспроизведение в репозитории после npm ci и установки requirements.txt:

```bash
python tools/compact_process.py --input path/to/4.bpmn --output-dir result --omit-documents reviewed_omissions.json --spacing-factors 1.3 1.6 --candidate-timeout 45 --search-seconds 45
```

Обычный run_v23.py оставляет строгий layout без удаления информационных элементов. Новый compact_process.py явно создаёт упрощённое представление и сохраняет его whitelist. Полный корпус r10 после этой доработки не пересчитывался.
