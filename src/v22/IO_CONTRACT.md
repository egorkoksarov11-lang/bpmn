# Контракт ввода/вывода v22 для автономного агента

## Назначение

Выполнить **только геометрическую оптимизацию BPMN-DI** уже согласованной бизнес-модели, не изменяя последовательность, типы операций, исполнителей и документы. Работа с регламентом, матрицей A/B/C/D и Semantic Freeze выполняется до вызова этого инструмента.

## Вход API/CLI

```json
{
  "command": "optimize",
  "input": "absolute-or-relative-path/process.bpmn",
  "output": "absolute-or-relative-path/process_layout.bpmn",
  "config": "config.json",
  "svg": "optional-preview.svg",
  "png": "optional-preview.png",
  "report": "optional-metrics.json"
}
```

`input` — файл BPMN 2.0 XML (`.bpmn` или `.xml`) с существующими BPMN-DI Shape и Edge. `output` — **другой** путь, всегда с расширением `.bpmn`. Конфигурация не содержит BPMN ID операций (кроме отдельного утверждённого перечня удаляемых document associations).

Перед `optimize` агент обязан вызвать `inspect`, проверить `compatible=true` и отсутствие критичных для его цели warnings. Синтаксис команд описан в README.

## Основной выход

1. `output.bpmn` — полный BPMN XML с изменённым `bpmndi:BPMNDiagram`. В strict-режиме XML вне BPMN-DI **побайтово эквивалентен после XML C14N**.
2. `preview.svg` / `preview.png` — необязательное визуальное представление. Превью не содержит новых бизнес-правил.
3. `report.json` — статус, вход/выход, проверка семантики, число элементов, метрики до/после и наличие разрешённых удалений.

Фрагмент отчёта:

```json
{
  "engine_version": "22.0.0",
  "status": "passed",
  "semantic_check": {"passed": true, "mode": "strict", "removed_associations": []},
  "geometry_before": {"total_bends": 40, "crossings": {"flow_flow": 6}},
  "geometry_after": {"total_bends": 40, "crossings": {"flow_flow": 6}},
  "artifacts": {"bpmn": "process_layout.bpmn", "svg": "preview.svg", "png": null}
}
```

Значения являются примером, реальные показатели вычисляются алгоритмом. Все длины — единицы BPMN-DI, а не миллиметры или пиксели.

## Ошибки и статусы

- `0` — файл создан, повторно прочитан, проверка бизнес-логики пройдена.
- `2` — ошибка входа/конфигурации/совместимости/тайм-аут/разрешённых удалений. **Новый BPMN не публикуется**.
- `batch` выдаёт `summary.json`, где по каждому файлу `status=passed` или `status=failed` с причиной; авария одного файла не прерывает всю очередь.

## Регулируемые настройки

Единственный источник параметров — JSON конфигурации, формат `schemas/config.schema.json`. См. таблицу всех параметров и их диапазонов в README. Агенту разрешено варьировать `horizontal_scale`, `candidate_scales`, `task_gap`, `document_gap`, `routing_order` и ограничения регрессии, выбирая лучшие геометрические метрики. Нельзя ослаблять `semantics.mode=strict` без отдельного документированного утверждения.

## Границы ответственности

- **Аналитический агент:** читает описание/формы, предлагает и согласует смысловые корректировки.
- **Контроллер Semantic Freeze:** формирует контрольный отпечаток согласованной модели.
- **Этот компоновщик:** меняет геометрию, выпускает метрики и проверяет отсутствие смысловых изменений.
- **Визуальный контролёр:** проверяет фактическую читаемость в BPMN-редакторе и A4/A3. Программное улучшение метрик ещё не означает готовность схемы к заказчику.
