# BPMN Universal Layout Engine v22

Локальный CLI/Python-инструмент для **безопасной визуальной оптимизации BPMN 2.0**. Работает с файлами разных бизнес-процессов, а не с фиксированными ID процесса № 01. Автоматически проверяет совместимость входа, перестраивает BPMN-DI, сохраняет размеры объектов, контролирует геометрию и независимо проверяет неизменность смыслового XML.

**Область универсальности ограничена:** поддерживается один процесс и одна BPMN-диаграмма в одном файле. Это **не полный движок для всех конструкций BPMN 2.0**. Сложные конструкции отклоняются на этапе `inspect`, а не обрабатываются с риском потери данных.

## 1. Установка

```bash
python -m pip install -e ".[preview,test]"
python -m bpmn_universal config --output my_config.json
```

Команда после установки: `bpmn-layout` (эквивалент `python -m bpmn_universal`). Для чтения BPMN нужен `lxml`; для PNG — дополнительный `cairosvg`, установочный extra `preview`. Интернет не нужен после установки зависимостей.

## 2. Входные данные

| Вход | Тип | Обязателен | Назначение |
|---|---|---|---|
| `--input` | файл `.bpmn` или `.xml` | да, режим `inspect`/`optimize` | BPMN 2.0 XML с **BPMN-DI** (координатами Shapes/Edges) |
| `--config` | JSON UTF-8 | нет | Настраиваемая геометрия, контроль семантики и лимиты; по умолчанию используется встроенная конфигурация |
| `--output` | файл `.bpmn` | да, `optimize` | Куда сохранить результат; исходный файл не перезаписывается |
| `--input-dir`, `--output-dir` | каталоги | да, `batch` | Папка с BPMN и папка результатов |

Поддерживаются: задачи и `callActivity`, обычные события и шлюзы, дорожки исполнителей, `sequenceFlow`, `association`, `dataInputAssociation`, `dataOutputAssociation`, `dataObjectReference`, `dataStoreReference`. Диаграмма должна содержать геометрию всех используемых объектов и потоков.

**Не поддерживаются и отвергаются заранее:** несколько процессов или диаграмм в одном файле; `messageFlow` между пулами; вложенное содержимое раскрытых подпроцессов; прикреплённые `boundaryEvent`; `textAnnotation` и `group`; недостающие BPMN-DI данные; информационная ассоциация с несколькими источниками/назначениями. Это явная зона расширения, не ошибка содержания процесса. Если эти конструкции есть, агент должен выбрать другой движок, а не применять v22 силой.

Внутренние действия, рабочие формы, регламент `.docx`/`.xlsx` **не являются входом компоновщика**. Они используются отдельным агентом анализа до Semantic Freeze. На вход v22 подаётся уже согласованный BPMN.

## 3. Выходные данные

| Выход | Тип | Значение |
|---|---|---|
| `--output` | BPMN 2.0 XML `.bpmn` | **Основной редактируемый результат**: исходная модель с изменённой BPMN-DI |
| `--svg` | SVG | Предпросмотр схемы, не источник смысловой модели |
| `--png` | PNG | Растровый предпросмотр; требует `cairosvg` |
| `--report` | JSON UTF-8 | Метрики до/после, сохранённые элементы, список разрешённых удалений, результат проверки |
| `--json` у `inspect` | JSON UTF-8 | `compatible`, `errors`, `warnings`, `counts`, `source` |
| `--summary` у `batch` | JSON UTF-8 | `total`, `passed`, `failed`, список файлов/ошибок |

Схема метрик: `schemas/optimize_report.schema.json`; схема параметров: `schemas/config.schema.json`. Метрики рассчитываются одним алгоритмом для исходника и результата.

**Коды завершения:** `0` — успех; `2` — ошибка валидации, тайм-аут, неподдерживаемый BPMN или регрессия. В `batch` ошибка одного файла не прерывает остальные, но итоговый exit code будет `2`, если хоть один завершился неуспешно.

## 4. Команды

Проверить совместимость, не изменяя BPMN:

```bash
bpmn-layout inspect --input my_process.bpmn --json compatibility.json
```

Оптимизировать с точным сохранением бизнес-логики:

```bash
bpmn-layout optimize \
  --input my_process.bpmn \
  --output my_process_layout.bpmn \
  --config examples/default_config.json \
  --svg my_process_layout.svg \
  --report my_process_layout.json
```

Пакетная обработка:

```bash
bpmn-layout batch \
  --input-dir examples/references \
  --output-dir output/batch \
  --config examples/fast_batch_config.json \
  --summary output/summary.json
```

CLI **не перезаписывает исходный файл**. Сначала записывает BPMN во временную папку, затем выполняет независимую семантическую проверку и повторный `preflight`, и лишь после этого сохраняет результат.

## 5. Регулируемые параметры (JSON)

См. `examples/default_config.json`. Полный список:

| Ключ | По умолчанию | Диапазон/значение | Влияние |
|---|---:|---|---|
| `geometry.horizontal_scale` | `0.90` | 0.35…1 | Целевое сжатие промежутков по X, **не самих блоков** |
| `geometry.candidate_scales` | `[0.8,0.85,0.9,1.0]` | массив 0.35…1 | Несколько вариантов горизонтального размещения для сравнения |
| `geometry.task_gap` | `26` | ≥0 | Минимальный горизонтальный зазор между соседними операциями на одном уровне |
| `geometry.document_gap` | `15` | ≥0 | Минимальный зазор при участии документа |
| `geometry.routing_order` | `short-first` | `short-first`, `long-first`, `name`, `reverse`, `flow-first-long`, `central-first` | Порядок прокладки взаимозависимых стрелок |
| `geometry.max_width_growth` | `1.05` | ≥1 | Предельный рост ширины (1.05 = +5%) |
| `geometry.max_avg_flow_length_growth` | `1.35` | ≥1 | Предельный рост средней длины основного перехода |
| `semantics.mode` | `strict` | `strict`/`approved-associations` | Без изменений логики либо строго разрешённое удаление зеркальных document associations |
| `semantics.approved_association_removals` | `[]` | список BPMN ID | **Только явные утверждённые ID**; не применяется в `strict` |
| `outputs.svg` | `true` | Boolean | Используется командой `batch` |
| `outputs.png` | `false` | Boolean | Используется командой `batch` |
| `outputs.report` | `true` | Boolean | Используется командой `batch` |
| `outputs.png_width` | `4400` | 300…12000 | Ширина PNG в пикселях |
| `execution.timeout_seconds` | `30` | 5…600 | Лимит поиска для одной схемы; на Unix обрывает затянувшуюся маршрутизацию |

Доли и длины выражаются в условных единицах BPMN-DI. `scale` влияет только на X-координаты; ширина и высота объектов **не меняются**. Приоритет по качеству: отсутствие наложений → отсутствие новых пересечений → уменьшение изгибов/ширины/длины.

## 6. Удаление визуальных дублирующих документальных ассоциаций

**Без явного согласования ничего не удаляется.** `strict` — безопасный режим по умолчанию после Semantic Freeze.

Если владелец процесса утвердил удаление конкретных зеркальных связей, создайте JSON-конфигурацию:

```json
{
  "version": 22,
  "semantics": {
    "mode": "approved-associations",
    "approved_association_removals": ["a10", "a26"]
  }
}
```

Проверяются одновременно: ID есть в исходнике, ассоциация соединяет задачу с документом, имеется противоположная зеркальная связь, и **все перечисленные ID действительно удалены**. Неверный ID блокирует обработку. Сам факт геометрической зеркальности **не означает**, что связь бизнес-избыточна; решение принимается в контуре согласования.

## 7. Архитектура и расширение

- `bpmn_universal/contract.py` — входной профиль, запрет опасных BPMN-конструкций, независимый semantic diff.
- `bpmn_universal/settings.py` — типизированные параметры, значения по умолчанию, проверка диапазонов.
- `bpmn_universal/engine.py` — компактная упаковка, ортогональная прокладка, повторная коррекция конфликтов и BPMN-DI.
- `bpmn_universal/cli.py` — команды, атомарный вывод, тайм-аут, пакетная обработка.
- `bpmn_refkit/` — низкоуровневое чтение/запись BPMN, геометрия и SVG (один общий модуль, без дублирования функций).
- `schemas/` — JSON-схемы входных настроек и выходного отчёта.
- `tests/` — проверки на процессе № 01 и различных референсах.

Дальнейшие расширения: несколько BPMNPlane, messageFlow, расширенные подпроцессы, boundary event, перестановка логических групп операций и проверка реальной читаемости A4. Новые типы нельзя добавлять только в парсер: нужны согласованные изменения маршрутизатора, проверки препятствий и тестов.

## 8. Статус универсальности

Проверка совместимости выполнена на **14** предоставленных референсах: **13** соответствуют поддерживаемому профилю. Один референс с `messageFlow` корректно отвергнут до запуска. Программный запуск и независимый семантический аудит проведены на процессе № 01, а также на разных кадровых референсах (включая входящие и исходящие информационные ассоциации). Результаты конкретных тестов см. в `output/test_results.json`.

**Это надёжный универсальный компонент для указанного класса BPMN, а не обещание полной совместимости со всеми возможностями стандарта.**
