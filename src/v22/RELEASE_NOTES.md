# Релиз v22 — результат аудита универсальности

**Статус:** универсален для документированного профиля **single-process BPMN 2.0 + BPMN-DI**. Не универсален для всего стандарта BPMN 2.0; неподдерживаемые конструкции отклоняет на этапе `inspect`.

## Исправления относительно v21

1. Удалена зависимость от названия процесса № 01: заголовок SVG берётся из атрибута процесса или имени BPMN-файла.
2. Добавлена независимая проверка совместимости (количество процессов/DI, корректность ID, полнота Shapes/Edges, неизвестные препятствия).
3. Добавлена поддержка `dataInputAssociation` и `dataOutputAssociation`, отсутствовавшая в парсере v21; оба типа маршрутизируются и учитываются в отчёте.
4. Удаление зеркальных документальных связей только по явному утверждённому списку ID; при неверном ID файл не сохраняется.
5. Встроено независимое сравнение смыслового XML до и после преобразования (в strict-режиме исключается только BPMN-DI).
6. Все параметры выведены в JSON, добавлены проверки допустимых значений и версии конфигурации.
7. Добавлены единые команды `inspect`, `optimize`, `batch`, `config`, коды завершения и JSON-схемы.
8. Добавлены пакетный режим, лимит времени на файл и атомарная запись результата.
9. Убрана самостоятельная CLI-ветка старого `engine.py`: единая точка входа — `bpmn_universal.cli`.

## Проверка

- Совместимость: 14 предоставленных BPMN-референсов → 13 поддержаны, 1 с межпуловым `messageFlow` корректно отвергнут.
- Регрессионные тесты: 8/8.
- Компоновка процесса № 01 в строгом режиме: 51 последовательный поток и 25 информационных связей сохранены, semantic diff = 0.
- Референс № 02: 13 → 7 изгибов; не добавлено пересечений; semantic diff = 0.
- Референс № 05: 39 → 18 изгибов, 1 → 0 пересечений основных потоков; semantic diff = 0.

`output/test_results.json` содержит перечень всех проверенных референсов и примеров.

## Оставшиеся ограничения

- Одиночный процесс и одиночный BPMNPlane.
- Нет динамической маршрутизации `messageFlow`/многопуловых процессов.
- Нет расширенной поддержки раскрытых подпроцессов, boundary event, текстовых аннотаций, multi-source data associations.
- Алгоритм компактизации не гарантирует идеальной укладки на A4 и не заменяет согласование бизнес-логики из регламента.
